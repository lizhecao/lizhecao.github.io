## Context

项目为 GitHub Pages 上的静态积木教程，当前基线含 61 个造型、12 门结构故事课、3 套完整场景，具备 SVG 分步显示、楼层筛选、成品预览、全屏、语音与离线缓存。核心数据中 `x/y/z/w/d/c/kind/zone/shell/role` 已能描述零件的位置、尺寸与用途；门、窗、半高板、坡顶、弧形和滑梯有不同形状。

当前固定投影没有真实相机；房间面积过小且家具重复，现有近景改善识别但没有增加房间内容。完整场景的数量与空间复杂度增加后，排序、遮挡和手动找视角会继续成为瓶颈。详见[调研](research.md)。

本轮为 OpenSpec 提案。实施假设为继续服务儿童与家长、主要使用 iPad 和手机、保持大颗粒积木和现有静态部署方式。

## Goals / Non-Goals

**Goals:**

- 自由检查前后左右，点击楼层即能清楚看到室内，能定位具体家具。
- 分步搭建和成品探索共用同一模型数据，查看行为不写入进度。
- 三套完整场景具有不同房间用途和可辨认家具，先以庭院之家验收。
- iPad 可用；完整场景 3D 可离线使用；其他造型、故事课、两段统计脚本正常保留。

**Non-Goals:**

- 本轮不实现 AR/VR、第一人称漫游、物理仿真、CAD 编辑、自由放置积木或无限场景生成。
- 不把全站旧造型都改成 3D，不以增加说明卡片代替室内重做。
- 第一版不实现连续剖切/楼层爆炸，不以虚拟隐藏墙体冒充实物拆装动画。

## Decisions

### 1. 采用独立 Three.js 查看器，直接消费现有零件数据

完整场景加入本地 ES 模块查看器。作品卡片、成品缩略图、旧造型和回退继续用 SVG；使用固定版本的 Three.js 与 OrbitControls，本地构建依赖包并保留 LICENSE，生产浏览器无需访问引擎 CDN。新增资源位于 `source/block-play/`，由既有 Hexo 跳过渲染规则发布。

不引入 React 等应用框架；model-viewer 更适合已有 GLB/glTF 资源，本项目选择保留按零件增量显示和元数据点选的直接控制。LDraw 作为特殊件几何缺口的后续备选，不在第一版引入完整库。

设适配层输出零件、步骤和对象映射。几何不复用 SVG 的 52/36 像素比例当成实物尺寸；标准砖的纵横比例先以真实大颗粒尺寸核对。`pieceHeight()`、半高网格与顶部连接规则继续共用。普通砖、板、基板、门、窗、坡顶、弧砖、滑梯都须有形状匹配的几何；未知种类回退，不展示成错误的长方体。

### 2. 楼层聚焦默认打开当前层外墙

用户看到的控件为：`全景 / 一层 / 二层 / 庭院`，以及 `打开外墙 / 合上外墙`、`俯视`、`复位`。屋顶可通过既有区域入口检查，不要求儿童操作技术参数。

- 全景：完整空间关系，屋顶和外墙正常显示。
- 楼层聚焦：隐藏其他楼层、上方楼板与屋顶；当前层及其地板实色显示；边界以轻量轮廓表示，默认隐藏当前层外墙实体。门窗边界仍可由轮廓识别。
- “合上外墙”：只恢复当前层所属外壳，不重新显示已隐藏的上层。
- 镜头按该层房屋与家具边界自动取景，不按整块庭院基板取景。旋转围绕当前层；选择家具后围绕该家具。
- 新模型的室内隔断也须区分墙体与对象；打开房间时以整件显示策略处理遮挡，实物坐标和材料表不变。

“只发光高亮”不能打开被遮挡室内；整栋半透明容易叠色和排序错误。第一版使用整件隐藏/轮廓，不需要连续裁切或透明层堆叠。上下楼层不漂浮错位，以免把查看变换误解成真实装配位置。

### 3. 家具按实例分组，可点选也可列表定位

新版场景继续用 `zone` 表示楼层/庭院，并增加 `roomId` 和 `objectId`；对象定义包含名称、用途与所属房间。床、书桌等类型 `role` 仍保留，但不同床拥有不同实例 ID，不能合并成一个对象。几何边界由零件计算，不额外维护另一套近景模型。

点中家具任一可见零件，选中整件家具，显示名称与组成并定位。只对当前模式允许显示的对象进行命中，已隐藏的屋顶、墙、未搭零件不得截获点击。屏幕家具列表提供等价操作，解决手指不易点中小物件的问题。

相机接近目标而不穿进模型。说明上的“看它怎么搭”跳到说明中的对应段落，不推进存储进度；儿童继续搭建仍使用明确的下一步按钮。

### 4. 相机状态与搭建状态分开

沿用现有 `current` 与进度存储逻辑；显示模型集合先由模式确定：搭建为 `steps[0..current)`，成品为全部步骤；之后才做楼层和对象筛选。不能先以 `current` 截断成品数据。

查看状态包含模式、楼层、外墙开合、选中对象与相机。进入成品预览暂存搭建视图，退出恢复原楼层、相机和层视图。切换模型重置查看状态。3D 下镜像对零件坐标和特殊件方向做映射，避免对实例使用负缩放造成面朝向问题。

搭建下一步可聚焦当前新零件并突出它；只在跨阶段/楼层或明确要求定位时调整相机，不在每次按下一步后强行重置用户旋转。若新零件不在用户选层，自动转到它所属层并告知。

### 5. 3D 画布不承担“点击下一步”

现有全屏图点击会推进步骤，这与单指拖动/点家具冲突。3D 画布只负责相机或选择，步骤按钮单独操作；SVG 下保持原有行为。区分短点按与移动/多指手势，触控画布内单指旋转、双指缩放和平移，画布外可以滚动网页。

为无手势经验的用户提供视角、缩放、复位按钮和可操作的家具列表。按钮触摸目标至少 44×44 CSS px；画布有文字名称和替代操作。相机自动过渡遵循减少动画的系统设置。

普通和全屏共用查看状态与一个活动 WebGL 上下文；全屏迁移画布并调整尺寸，而不在作品卡片和每个家具近景额外创建上下文。离开 3D 销毁不用的资源。

### 6. 丰富家具需要先扩大实际室内

重做 3 套场景使用新 ID，例如 `scene-courtyard-home-v2`，旧模型继续支持已保存进度与直接进入教程。新版第一层/第二层按各自生活用途布局，家具具有靠背、扶手、隔间、床头等可辨认结构；不只调整颜色和名称。候选住宅外轮廓约 16×12 凸点，实际选定尺寸以基板、承托和庭院空间验证为准。

家具先作为实际可搭小模块设计，再把同一模块放进完整模型。每个模块都有清楚的搭建段和材料表，零件仍逐块教程。较长作品按房间/家具/墙体分阶段，不要求一口气完成。

### 7. 按需渲染和本地离线资产

普通砖与凸点共享几何，重复几何采用实例化；按可见状态维护实例到零件/对象的映射。材质、光源和阴影保持简单，不首先引入后期特效或高分辨率贴图。拖动/过渡时更新帧，静止时不持续无效渲染；限制像素比以适应 iPad。

先记录现有模型和 500 块合成场景的加载、旋转、绘制调用及资源释放；目标为参考 iPad 上 30 秒拖动的 P95 帧间隔不超过 33.3ms。该目标需实测，桌面 Playwright 不替代 Safari 或 GPU 验收。

模块按需导入，但本地模块包、所有内部依赖和静态几何必须加入同作用域核心离线资源。声明“离线已准备”前完成必要资源缓存；版本同时更新 PWA 与 SW。首次打开 3D 时若已离线，也不能缺依赖。初始化失败或上下文丢失时，保留进度和区域并显示现有 SVG。3D 的可用性不得决定普通网页能否使用。

## Risks / Trade-offs

- [只换渲染器仍然简陋] → 家具和房间内容作为独立验收，先完成一套旗舰场景。
- [门窗/滑梯等被误画成盒子] → 特殊件独立形状与连接位置测试，多角度人工核对；暂不支持的种类回退。
- [可旋转后触控误推进] → 3D 画布解绑旧点击推进；拖动、点家具、多指操作回归检查进度。
- [新场景步骤改变旧进度含义] → 新模型 ID，不按旧数字强行迁移；旧教程可继续。
- [透明壳仍挡点击或出现视觉错误] → 默认整件隐藏，轮廓不参与家具命中。
- [iPad 绘制慢或上下文过多] → 一个活动查看器、实例化、按需渲染、像素比控制、资源释放；实机不达标则继续 SVG。
- [离线模块漏缓存] → 构建时枚举依赖，浏览器离线首次进入 3D 的回归。
- [实例批次变化后选错家具] → 每次可见集合改变都更新 instance→part→object 映射并测试。
- [特殊件实物接口不同] → 配套件说明与实物打样，不用网页形状证明一定可装配。

## Migration Plan

1. 在独立实现 worktree 先编写状态/命中/可见性测试，打样现有庭院之家；网页继续保持旧版。
2. 固定引擎版本，完成几何与相机校验；完成真实 iPad 测试后再接入完整场景入口。
3. 设计并验收新版庭院之家，随后重做树屋与幼儿园。旧 ID 与进度键保留，新 ID 从零开始。
4. 检查其他造型、故事课、语音、成品预览、全屏与两段统计代码。生成静态文件，只同步 block-play 目录发布。
5. 比较线上文件并跑线上 3D/离线回归。若失败，先切回 SVG；需要回滚发布文件时同时发布新的 SW 版本，避免旧坏缓存持续生效。

## Open Questions

以下是实施阶段需取证的未知，不阻塞本轮文档提案：

- 参考 iPad 的型号/iPadOS 待记录；首次性能打样前需确认实机测试来源。
- 门、窗、弧砖、滑梯实物的精确比例与接口待核对；不把 SVG 像素当测量结果。
- 新房屋尺寸、完整家具数量与分段先后需在搭建布局验证后确定。
- 儿童无文字辨认家具的反馈需实际收集，不能把代码断言作为可辨认度的证明。
