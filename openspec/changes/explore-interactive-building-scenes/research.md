# 大型积木场景查看方式调研

调研日期：2026-10-09。代码基线：hexo `2696366`。结论来自当前源码和一手产品/技术文档；尚未制作 3D 原型或做实机性能测试。

## 结论

建议采用真实 3D 查看，并把“楼层聚焦、打开外墙、家具定位”作为默认的室内查看流程。旋转解决换角度，隐藏遮挡解决看进去，重新设计家具和房间解决内容简陋；三者分别有用，不能互相替代。

## 当前网页的限制

- `app.js` 的 `svg()` 通过固定投影和绘制排序展示场景；“换个方向看”只是镜像。当前区域筛选可以隔离一层，但不能从另一侧观察家具。
- 庭院之家、森林树屋的房屋外轮廓为 4×4 坐标单位，墙各占一单位，室内仅 2×2 单位；一个单位对应两格凸点，约为 4×4 凸点。每层只有 6 块室内零件，组成一张床、一张桌和一本书。
- 幼儿园外轮廓为 6×4 单位，室内约 8×4 凸点；一层 7 块家具，二层 6 块。房间用途基本相同。
- `zone`、`shell`、`role` 和逐件步骤已经存在，可以复用。缺少多个同类家具的实例 ID 和房间分组。
- 全屏主图目前点击就进入下一步。引入旋转后必须解除画布点击与步骤推进的绑定，否则拖动或点家具会误操作。

## 查看方案比较

下面是基于本项目场景的设计判断，不是竞品的量化测试。

| 方案 | 解决的问题 | 局限 | 建议 |
| --- | --- | --- | --- |
| 固定图＋家具近景 | 识别家具名称和组成 | 看不到空间关系与背面 | 保留作 SVG 回退、家具说明 |
| 单独 3D 旋转 | 从前后左右看 | 屋顶、楼板和墙仍会挡室内 | 作为基础能力 |
| 只高亮某一层 | 容易知道选中了哪层 | 高亮本身不能消除遮挡 | 与隔离楼层一起做 |
| 3D＋楼层聚焦＋打开外墙 | 既能看后面，也能直接看室内 | 需要分组和相机控制 | 第一版默认方案 |
| 连续剖切滑杆 | 任意位置切开大型建筑 | 控件复杂，会切碎一块砖，切口还需处理 | 暂缓，先整件隐藏 |
| 楼层爆炸图 | 解释楼层如何叠起来 | 部件离开实际位置，家具还是可能被挡 | 后续教学模式，默认不使用 |
| 第一人称室内漫游 | 有探索感 | 小房间易穿墙，找物件与退回更难 | 本轮不做 |
| 多张预设角度图片 | 低成本切换不同方向 | 图片数量膨胀、没有任意定位 | 可作为回退与快捷相机视角 |

默认交互：点击“一层” → 隐藏二层与屋顶 → 镜头对准一层 → 打开一层外墙并显示边界轮廓 → 拖动看后排，或点沙发/书柜定位。点击“全景”恢复完整房屋。成品模式始终使用完整零件；搭建模式仅使用已搭零件。

## 室内内容方案

先增加房间面积和通道，再加入家具。以庭院之家为打样，外轮廓可从约 8×8 凸点扩大到约 16×12 凸点，继续尝试在 24×24 基板上容纳院门、树和滑梯；这是布局候选，不是已验证的搭建图。

| 场景 | 一层 | 二层 |
| --- | --- | --- |
| 庭院之家 | 客厅：有靠背/扶手的沙发、茶几；餐厨区：餐桌和座位、厨房台面与水槽/灶台 | 卧室：床头、枕头、床头柜、衣柜；书房：书桌、座位、书架 |
| 森林树屋 | 营地休息区：长凳、物资柜、桌台 | 树屋睡眠与观察区：床铺、望远观察台、储物架 |
| 幼儿园 | 教室/阅读区：多组桌椅、分格书架、玩具收纳 | 午睡/活动区：多张小床、储物柜、活动桌 |

家具必须有可辨认的结构差异。例如椅子有座面和靠背，柜子有隔间/门形，床有明确床头与枕头，沙发有扶手。名称帮助识别，但不能把同一个方块换名字充当各种家具。仍采用大颗粒和现有配套件，材料表、零件位置与教程保持一致。

## 技术方案比较

| 方案 | 适用情况 | 本项目判断 |
| --- | --- | --- |
| Three.js＋OrbitControls，按当前零件数据生成几何 | 有坐标、步骤、分组，需要细粒度显示与点选 | 推荐；保留数据源，单独加入查看器 |
| model-viewer | 已有 GLB/glTF 展示资源，需要快速嵌入 | 可展示模型，但当前还需处理每步零件和楼层，额外引入模型导出管线，暂不优先 |
| LDrawLoader＋零件库 | 需要精确零件模型且有对应资产 | 后续特殊件精度方案；先核对大颗粒零件是否覆盖，再取少量必需文件 |

[OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)提供围绕目标的旋转、缩放和平移；[Raycaster](https://threejs.org/docs/pages/Raycaster.html)可用于点选；[InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)可减少重复几何的绘制调用。[model-viewer 示例](https://modelviewer.dev/examples/scenegraph/)说明了其 GLB/glTF 材质/变体 API 的范围；上述适配判断由本项目需求推导。

[Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)当前需要 WebGL 2，并指出透明物体排序并非总能正确处理，因此不把“整栋透明”作为室内默认方案。[Material](https://threejs.org/docs/pages/Material.html)支持裁切平面，但第一版以整件隐藏实现打开外墙。

[LDrawLoader](https://threejs.org/docs/pages/LDrawLoader.html)文档指出零件库较大、多个依赖请求需要打包优化。[LDraw 官方头部规范](https://www.ldraw.org/article/398.html)和[零件库政策](https://beta.ldraw.org/documentation/policies-and-procedures/parts-library-policies-and-faq)说明许可需按具体零件文件核对。第一版不整库下载，也不假设所有大颗粒门/滑梯已有可用资产。

## 实现前的验证门槛

- 用现有庭院之家验证 3D 数据映射、门窗开口、弧形/坡面、滑梯高端位置与凸点，不把特殊件都画成盒子。
- 未搭完时查看成品的二层，必须出现完整家具；旋转、缩放、楼层和家具点选不能改变进度。
- 在真实 iPad Safari 上测旋转与点选。暂定 500 块场景持续操作 30 秒的 P95 帧间隔不高于 33.3ms；这是待测目标，不是已测结果。记录设备、iPadOS、浏览器、画布尺寸和帧数据。
- WebGL 初始化失败或上下文丢失要能回到 SVG。使用本地固定版本依赖，离线重载能首次打开 3D 查看器。
- 在手机和 iPad 请家长/孩子不看家具名称，辨认床、椅子、沙发、书柜；反馈仍不清楚时改结构，不只补文案。

## 推荐实施顺序

1. 现有庭院之家做查看器打样，先解决手势、遮挡、楼层和预览状态。
2. 完整重做一套更宽敞的庭院之家，确认能看清、能辨认、能按步骤搭。
3. 把同一查看方式应用到另两套，并按各自场景重做内容。其余原有造型和结构故事课保留。
4. 如实机或特殊件验证未通过，继续保留现有网页，修正原型后再进入发布阶段。
