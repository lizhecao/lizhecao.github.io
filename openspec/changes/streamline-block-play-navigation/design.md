## Context

当前正式源为 `origin/hexo` 的 `74a792c`，发布为 `origin/master` 的 `142c117`，SW/PWA 为 `20261010-v18`。`index.html` 把造型库、搭建、结构故事、创意任务与安装连成一张长页；`chooseModel`、卡片和「拿积木试一试」通过 `scrollIntoView` 找下方内容，放大另外使用 `zoom-dialog`。六个完整场景已经支持本地 Three.js、按层开墙、家具实例、相机记忆和 SVG 回退，图形/故事/材料均可复用。

本次用户先讨论交互，再要求 OpenSpec proposal。采用「栏目 Tab + 独立详情页面」同时解决栏目切换和进入内容，沿用现有名称「结构实验室」。此前讨论的成品默认 3D、室内步骤近景纳入本次实现范围。本文只规划，不改产品代码。

## Goals / Non-Goals

**Goals:**
- 选择作品/实验/任务后一次点击进入对应页面，不滚过其他栏目。
- 浏览器返回、页面内返回、刷新与离线都能找到正确内容，列表选择上下文与已有进度保留。
- 成品直接进入三维，室内分步直接看清当前家具和新增积木，图案操作不会误推进。
- 复用静态部署、现有零件/故事、单个三维上下文及当前离线/回退机制。

**Non-Goals:**
- 按 2026-10-20 用户追加要求新增 12 个原创造型；不重排原模型/故事/家具布局，不将普通造型扩展成三维。
- 不引入登录、云同步、后端、框架、独立 HTML 文件生成或新的引擎。
- 不恢复独立预览站，不加入室内漫游、物理仿真、连续剖切或自动遮挡计算。

## Decisions

### 1. Tab 管栏目，独立路由管内容

手机固定底部四个栏目：造型库、完整场景、结构实验室、创意任务。iPad/桌面使用相同栏目，导航可置于顶部；都必须明确当前栏目。造型库保留已有筛选、搜索与大作品分类，完整场景提供六个场景的入口。安装说明与离线状态归入设置，头部保留可达入口。

栏目入口呈现目录/卡片，搭建、故事实验和任务内容进入各自详情。搭建与成品查看页占据当前屏幕，固定返回/关闭和主要操作，不显示占用画布的底部 Tab；返回后恢复栏目。实验与任务详情允许自身内容滚动，但不包含其他栏目或全部教程。

单纯把锚点变成 Tab 外观仍会把用户带到长页中间，无法解决问题；拆成多份 HTML 则需重复加载内容、协调全局变量与缓存。采用同一静态 HTML 中的互斥页面视图：用户获得独立页面跳转，资源继续复用。

### 2. 小型 hash 路由，覆盖返回与直达

建议路由如下，均以正式 `/block-play/` 为入口：

| 地址片段 | 页面 |
| --- | --- |
| `#/models` | 造型库 |
| `#/scenes` | 完整场景目录 |
| `#/lab`、`#/lab/<labId>` | 实验目录、单个故事实验 |
| `#/missions`、`#/missions/<missionId>` | 创意任务目录、单个任务 |
| `#/build/<modelId>` | 准备材料与分步搭建 |
| `#/preview/<modelId>` | 成品查看 |
| `#/ideas/<modelId>` | 当前作品的三个自主创作挑战 |
| `#/settings` | 安装、离线说明及状态 |

路由只编码栏目和稳定对象 ID；分步进度继续读写现有 `block-lab-progress-v4`，每次下一步不增加浏览器历史。实验使用现有 `LABS.id`，创意任务增加明确稳定 ID，不用显示位置作为 URL 标识。不实现一套通用路由框架，仅集中处理解析、打开页面、历史和返回。

显式卡片/Tab 导航产生历史记录，默认入口与旧锚点规范化使用替换记录。实现必须避免程序更新 hash 和 `hashchange`/返回事件引起重复进入、重复保存或双渲染。旧 `#choose/#lesson/#learning/#mission-section/#install-section` 映射到新页面，未知 ID 提示并返回所属目录，不修改任何进度。

列表筛选、搜索、加载数量和滚动位置，以及实验故事步骤/对照状态，保存在当前会话的页面状态中；历史记录关联来源页。返回和前进恢复它们。刷新能够由路由和已有本地进度重建正确详情，列表筛选/相机无需跨刷新持久化；不更换进度键，不在 URL 写大段页面状态。

直达成品链接没有来源时，关闭去同模型搭建页；直达搭建页返回所属作品目录；实验/任务直达返回各自目录。页面进入后焦点移到标题，隐藏页面不能被键盘或读屏访问，路由页面标题与当前内容一致。

### 3. 搭建和成品分别是页面状态

首次打开未搭作品进入准备材料状态（第 0 步），按「开始搭」显示第一步；已搭作品从保存步骤继续。模型 ID 和旧/新版独立进度均保持。搭建页拥有足够大的主图、当前步骤说明、拿取积木提示和固定前后按钮；完成后的自主创作进入 `#/ideas/<modelId>`，展示现有三个挑战并可返回作品，不再滚到全站长页尾部。

六个完整场景点击「成品预览」直接打开沉浸式 3D 页面，完整模型数据按所选楼层显示，提供旋转/缩放/俯视/复位/家具与关闭；正常状态不提供「查看搭建图」模式切换。其余造型打开静态成品页。无 WebGL、初始化失败或上下文丢失时在同一路由自动显示 SVG 成品，保留选层和关闭按钮。

成品状态与搭建状态使用现有分离相机/选层/外墙机制；关闭恢复进入前模型、当前步骤、家具关注与搭建视角。进入成品、关闭、切 Tab、点击图案、点家具与任何手势都不写搭建进度。前后、重新开始等明确搭建操作才写进度。原 SVG 全屏点击推进同步移除，避免故障回退时重新引入误操作。

路由和现有 `zoom-dialog` 不得同时驱动两个查看器。优先复用一个页面主图与现有单查看器，必要的普通造型放大保留为同页面内查看操作；关闭或切到目录/实验后释放或停止三维渲染，重新进入根据页面状态恢复。

### 4. 室内步骤按「楼层 + 家具」引导

根据当前零件的 `zone`、`objectId` 与房间映射识别室内步骤。新版使用家具实例 ID；旧场景复用现有 `role` 到家具 ID 的适配，无法识别家具的楼板/墙体步骤按楼层展示。进入室内家具步骤自动启用 3D，隐藏上层/屋顶，打开当前层外墙；地板、房间边界和必需承托保留。

镜头在首次进入家具、跨家具或跨楼层时定位；同一家具连续步骤保留用户旋转/缩放，不逐块重置。可使用完整家具的边界计算稳定取景，但实际渲染只包含当前与之前步骤的零件，不提前显示完整家具、后续家具或未来楼层。镜像后取景与位置提示必须使用镜像坐标。

当前新增积木显示高对比描边，并显示连接/放置位置轮廓；近景边上继续展示现有「现在拿这一块」与位置说明。近景强调当前对象，弱化其他家具，保留支撑参照；用户可回到本层全景，再通过「回到本步视角」恢复推荐近景，操作不推进或清零。

半透明/轮廓提示只表示当前步骤的放置位置，不改变积木几何或物理结构。同一个家具开始阶段零件很少时，也需有地板和方位参照；禁止只显示孤立的一块积木。无三维时，SVG 按当前楼层/家具裁剪放大，并保留本步标记、材料提示和步骤按钮。

### 5. 静态站、离线与验收继续沿用

Hash 不参与服务端取文件，GitHub Pages 深链接和离线刷新继续命中 `/block-play/`。若增加路由模块须加入 CORE，更新 SW 与 PWA 的相同新版本；验收从实际 v18 缓存升级，不能仅测空缓存。两个统计脚本各保留一次，本次不追加虚拟页面埋点，也不更换追踪服务。

手机/iPad 主要操作目标至少 44×44 CSS px；处理安全区、横竖屏、底部控制栏，保证主图/当前步骤/前后按钮不被遮挡。优先利用可用屏幕展示图与短说明，长材料和家长说明在本页展开，不靠全站下拉。真实 iPad 的可见性和触摸验收仍需要设备记录，桌面模拟不能替代。

## Risks / Trade-offs

- 页面隐藏后原选择器可能仍命中不可见内容 → 路由集中管理 `hidden`、焦点与当前容器，浏览器回归只操作可见页面，并检查不存在栏目长页拼接。
- 卡片和 `chooseModel` 有重复初始化逻辑 → 统一到一次页面进入流程，路由不调用旧滚动处理；用保存第 80 步、往返实验与成品用例发现重复重置。
- 自动聚焦可能抹掉手动视角或把支撑一起隐藏 → 按楼层/家具改变才定位，稳定取景；以床、桌与同层多床截图和可见零件集合验证。
- Tab/详情/刷新与返回来源组合复杂 → 明确定义来源与直达兜底，测试卡片进入、返回/前进、设置返回、刷新、旧锚点及无效 ID；步骤不进入路由历史。
- 默认室内 3D 会增加启动压力 → 复用本地依赖、按需加载和一个上下文，及时停渲染/释放；失败自动近景 SVG，记录真实 iPad 结果。
- 现有长页和全屏回归会失去旧 DOM 假设 → 保留模型/离线/几何断言，按新页面重写交互入口，不通过删除失败断言掩盖进度或故障问题。

## Migration Plan

1. 从最新 `origin/hexo` 新建实现 worktree。先写路由/视图状态与浏览器失败用例，再实现导航和页面互斥；现有生产与旧 OpenSpec change 不提前修改。
2. 接入搭建/成品路由与明确步骤操作，再实现室内引导、返回恢复与 SVG 近景回退。现有模型、故事和数据版本不迁移。
3. 运行模型/故事/导航/3D/回退/iPad 尺寸/离线测试，从 v18 真实快照升级验证旧进度与离线直达。记录真实 iPad 反馈，未测项明确保留。
4. 单独发布 worktree 从最新 `origin/master` 起步，构建后只同步 `block-play/`，推送非 master 分支后按已有正式上线授权发布；验证路由、返回、成品与室内步骤实际线上行为，不重新发布 preview。
5. 回滚恢复已知可用 `block-play/` 资产，同时赋予新的 SW/PWA 版本。旧锚点兼容与已有进度保留；回滚不涉及博客/DCA或预览退役脚本。
